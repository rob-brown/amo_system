How much is decryptable

Green is the range covered by the amiibo-layer crypto: v2 bytes 0x000–0x207, v3 bytes 0x000–0x247 (584 of 2048).

Amiibo layer, done

AES-128-CTR over 392 bytes (0x014–0x033 and the 360-byte app data), HMAC-SHA256 for the tag and data hashes. The same retail key file works for both formats. v3 only changes where the HMAC and app data sit.

Game layer, not done

The KAR payload inside the app data, the blocks after 0x248 and the SRAM authentication bytes are not covered by the amiibo key. We keep them byte for byte so a decrypt followed by an encrypt returns the original file.

Things the dumps showed

  • Format is detected by size, and for encrypted v3 by the ID format byte at 0x05B being 03.
  • A decrypted v3 binary is 2048 bytes: the 520-byte internal layout, the 64 reserved bytes, then everything from 0x248.
  • The machine in Kirby Air Riders follows the SRAM block, not the encrypted data. Changing the UID is risky: with the payload's own machine the game shows error 2115-0548, and a UID the console has never seen gets "can't participate in matches". UIDs it already knows work (see the UID notes).
